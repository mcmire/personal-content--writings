[Obsidian](https://obsidian.md) is the tool I use to keep digital notes — to jot down thoughts and ideas about life and work, plan and track side projects, write long-form content like this, and more.

In this post, I'll document how I use Obsidian, how I've tweaked it to fit my needs, and how that's evolved over time.

## How I use Obsidian now

### Directories and tags

I still find directories useful, but there are three broad categories of notes that I use on a daily basis:

- `Diary/` — Date-based. Most of these entries are conversations between different voices in my head. I'll let them say what they want to say and move on. I don't typically go into a lot of detail (good luck to whoever reads this in the future!).

- `Log/` — Date-based. Ostensibly a "development log", but really it's the opposite of `Diary/`. These entries tend to be more rounded out, and I tend to revisit them multiple times per day. If I read an interesting article about politics, life, or work, and it inspires me, I'll write out my thoughts. If I'm reading a book, I'll keep notes. %%If I have an idea for a new side project, I'll map it out.%%
  
  And if I'm actively working on a project, I'll "live blog" the experience, noting the problems I'm facing and the solutions as I attempt to solve them. I have found this workflow in particular to be incredibly valuable. For instance, if I put a project on hold and come back to it a year later, I can go back in my notes, see I was headed when I left off, and I can very easily pick up the thread again.

- `Notes/` — Non-date-based. Most of my old notes are here, and I have yet to migrate them to a better format. Even so, I still tend to use this category to hold information that I think deserves a bit more structure, I want to keep together in one place, or I feel like would be buried if I left it in a journal entry. Each note tends to center around a concept or theme. For instance, when I do research for big-ticket items (e.g., baby strollers, cars, etc.) or make plans for trips, I'll add a note here. There are also simple lists of things such as potential baby names, etc.

 Beyond this structure, I've recently begun using tags to link notes by broader themes. This is a practice I already follow when posting bookmarks to [Pinboard](https://pinboard.in/), and I already have a list of tags %%in my head%% that I frequently use, so tagging notes is %%a%% pretty easy. %%transition.%% For instance, if I'm thinking about AI, I'll use the tag `#artificial-intelligence`; if I'm thinking about career goals or dreams, I'll use `#future-work`. I also have tags for `#philosophy` and `#physics` and `#music-analysis`.

### Core plugins

I use a pretty small set of core plugins:

- **Quick Switcher** + **Files**. Most of the time I know what I'm looking for and can jump to it, but sometimes I just want to look at a file tree (and it's a better interface to perform actions like renames).
- **Command Palette**. I like this paradigm that's been integrated into apps over the years. It reminds me of Spotlight on my Mac.
- **Page Preview**. It's useful not to have to jump into a note to see what's inside it.
- **Search**. I'm not sure what I'd do without this :) 

In contrast, here's what I've disabled:

- **Backlinks**, **Outgoing Links**, or **Graph View**. I imagine these would be more useful if I were following Zettelkasten, but I don't. Maybe some day.
- **Canvas**. Maybe if I were doing intense research I might need it, but I tend to only use features that I can both on mobile and desktop (see Syncing below), so I haven't given this a go yet. It's cool that the JSON representation is opensource, though.
- **Bases**. I think the Obsidian team has done a great job developing this feature. It certainly looks appealing. But coming from my experience with Dataview, I'm wary of making my vault too complex again.
- **Daily Notes**. Obsidian only supports creating daily notes in one location, but as mentioned above, I want to have two date-based directories. (I don't use Templates for a similar reason.) I use QuickAdd instead (see below).
- **Outline** or **Properties View**. I don't usually have documents that are so long that I have trouble scrolling through them. And I don't need to see properties across all of my notes.
- **Sync**. I use my own solution (again, see below).
- **Web Viewer**. I usually have my browser open on either my laptop or phone, and I want to keep all of my open tabs together in the same app.
- **Word Count**. I don't really care how long my notes are, and for blog posts like these, I write and rewrite thousands of words and hide the vast majority of them, so a word count doesn't really help anyway.

### Community plugins 

I try out new plugins from time to time, but here are the ones that have stuck:

- **Commander** + **QuickAdd**. I use the combination of these plugins to add a button to the ribbon that allows me to generate either a diary entry or a log entry using one of two templates I've set up.
- **Custom File Extensions**. This plugin allows me to edit MDX files (more on that later).
- **Outliner**. Provides some great quality-of-life features for working with lists. On my laptop, I can press `Cmd-Shift-Up` and `Cmd-Shift-Down` to move a list item up or down, respectively. On my phone, I have hotkeys to do the same thing.
- **Smart Typography**. This helps me write on my phone because I can type `--` to get an em-dash and `<-` or `->` to get ← and → respectively.
- **Vimrc Support**. I use Obsidian with Vim keybindings enabled. This plugin extends that by allowing me to see when I'm in insert mode vs. normal mode. It also allows me to add custom settings via a `.vimrc` file (for instance, I map `j` to `gj` and `k` to `gk` to be able to navigate through wrapped lines, and I use `set clipboard=unnamed` to use the system clipboard).

### Vaults and devices

As I explained in a [previous post](./behind-the-site.mdx#putting-it-all-together), the content for the site you see right now — the layout and styles — lives in a separate repo from the site itself. I do this for two reasons:

1. If I ever want to change the way my site looks or even rebuild it using a different tech stack, I don't have to touch the content repo.
2. I can keep the Git history between the two isolated.

In addition, I use Obsidian on not only my laptop, but also my phone. %%I've found that each device has its own advantages. ## Syncing Obsidian between devices 

I don't use Obsidian Sync. It definitely sounds useful, and I'm sure it's easy to set up. But I like to keep my Obsidian vault in Git so I have ultimate control of not only the current versions of the files in my vault, but also any historical versions as well. %%But I'd like to have control over every part of my data, and this includes historical versions of files.%%

Nor do I use the Obsidian Git plugin. As the README states, [it is very unstable on mobile](https://github.com/Vinzent03/obsidian-git?tab=readme-ov-file#-mobile-support-%EF%B8%8F--experimental). I often use Obsidian on my phone during the day, so that doesn't work for me.

Instead, I use a custom solution, which I will detail below.

### Sync script

I host my vaults in private repos on GitHub. The work of syncing changes between the local and remote versions of my repo is done by a custom [shell script](https://gist.github.com/mcmire/33f5b5e1a7c96049424c17fb3060a4e0). (I keep in the vault repo under `./scripts/sync.sh` so I can run it manually if I need to.). This script runs the following steps:

1. Adds files ending in `.md` and `.mdx` and files in `.obsidian` that have been changed
2. Creates a new commit with the message "Automatic sync"
3. Pulls new commits in, rebasing any pending commits on top of them
4. Pushes the `main` branch
5. Handles submodules (see below for why this is important).

A few notes about this script:

- It uses a lockfile to ensure that only one instance of the script is running at a time.
- Even if the script runs, if there are no changes, then no commit will get created and nothing will get pushed.
- The script also supports syncing nested repos (see [below](#updating-this-site-via-obsidian) for why this is important).
- I've configured Git to ignore `.obsidian/workspace.json` and `.obsidian/workspace-mobile.json`, so if these are changed then nothing will happen. This files holds ephemeral data like recently opened files that I don't need to capture in Git.

Now, having a sync script is great, but I don't want to run it manually. To emulate what Obsidian Sync does — and to make things work the same way across my laptop and phone — I have to employ a bit of ✨ magic ✨.

#### Desktop

On my Mac, I have two LaunchAgents set up:

- One runs a daemon which executes a wrapper around the sync script when any file within the Obsidian vault is changed. This wrapper performs debouncing, so that no syncing will occur while I'm actively editing a file, but only after I pause for 2 minutes.
- The other runs the same script every day. This handles the case where I'm writing something but I close my laptop before the script has a chance to run.

Both of these LaunchAgents are included in my [`dotfiles`](https://github.com/mcmire/dotfiles) repo, and they get installed when I run `bin/manage install`.

#### Mobile

On mobile, I use the [Automate](https://llamalab.com/automate/) app to mimic the same process I have on desktop. (As far as I know, this only works on Android; on iOS you could probably use [Shortcuts](https://support.apple.com/guide/shortcuts/welcome/9.0/ios).)

I have one workflow that looks like this:

![Automate workflow](./how-i-use-obsidian/automate-workflow.webp)

In short:

- When I switch away from Obsidian, or when I lock my phone, the sync script is executed.
- The sync script is also executed every 30 minutes automatically (in case either of the two checks above don't work properly).
- Like on desktop, executions of the sync script are debounced by 2 minutes. If the timer is running and I switch back to Obsidian or unlock my phone, the timer is canceled.
- The workflow uses a plugin block, using [Termux:Tasker](https://wiki.termux.com/wiki/Termux:Tasker), to run the sync command. (It may be that I can use the "Shell script" action, but I haven't tested it out.)

The other workflow is used to simply run the sync script on demand.

To set this up, I followed these steps:

- I downloaded [F-Droid](https://f-droid.org/) and [Termux](https://termux.dev/) from the Play Store, and I downloaded Termux:Tasker and Automate from F-Droid.
- I opened Termux and ran `termux-setup-storage` to allow access to the SD card.
- I used `gh` to clone my Obsidian vault repo in `shared/storage`. I've found that `gh` works best over plain `git` because it handles authentication for private repos very smoothly.
- I created a symlink to the vault repo in the home directory for quicker access.
- I used `gh` to clone my `dotfiles` repo, also in the home directory. To install them, I first ran `pkg install ruby`, and then ran `bin/manage install`.

### Preparing the vault repo

There are a couple of ways I've configured my Obsidian vault repo to work best with syncing.

First, I've instructed Git to ignore the Obsidian workspace JSON files (since they tend to collect conflicts easily) as well as trashed files:

```
.obsidian/workspace.json
.obsidian/workspace-mobile.json
.trash
```

Second, I've installed [Git LFS](https://git-lfs.com/). This way, if I want to add images or other media (such as audio files from the Audio Recorder plugin), I don't bloat the repo.


## Updating this site via Obsidian

One recent change I made was to integrate my site into my Obsidian vault.

As I explained in a [previous post](./behind-the-site.mdx#putting-it-all-together), the site you see right now — the layout and styles — lives in a separate repo from the content you're reading. I do this because if I ever want to change the way my site looks or even rebuild it using a different tech stack, I don't have to touch the content repo, and the Git history between the two will stay isolated.

Even with this setup, I found it more difficult to publish new blog posts than I liked. First, I had to be at my laptop to write a post. Then, I had to follow these steps:

1. Switch to my terminal
2. Navigate to my content repo, open it up in Neovim
3. Start writing
4. Realize that I want to see a preview
5. Open my content repo in VSCode, open up a Markdown preview
6. Remember to switch back to terminal and commit when I was at a stopping point
7. Finish the post, realize that I want to see what my post really looks like
8. Push up a branch
9. Make a pull request
10. See the post online

In contrast, Obsidian is so painless to use that I can open it anywhere, anytime, and it just works. It finally dawned on me: why can't I integrate my site and content repos into my Obsidian vault repo so that I can write blog posts the same exact way I would make a new journal entry or a note?

### Adding submodules

I needed some way of bringing all three repos under one umbrella. I debated using subtrees (or something similar, such as [git-subrepo](https://github.com/ingydotnet/git-subrepo)) to accomplish this, but both approaches require keeping some amount of history in the parent repo, and I didn't want that.

In the end I decided to use submodules. The hierarchy of my vault repo now looks like this:

```
obsidian-vault/
  _modules/
	  elliotwinkler.com/
		  modules/
			  personal-content--writings/
			...
	Diary/
	Log/
	Notes/
	...
```

That is, `.gitmodules` in the vault repo looks like this:

```
[submodule "_modules/elliotwinkler.com"]
        path = _modules/elliotwinkler.com
        url = https://github.com/mcmire/elliotwinkler.com
```

And `.gitmodules` in `_modules/elliotwinkler.com` looks like this:

```
[submodule "modules/personal-content--writings"]
        path = modules/personal-content--writings
        url = https://github.com/mcmire/personal-content--writings
```

### Updating the sync script 

The sync script also supports submodules. This is a bit tricky because if new changes are brought into a submodule via `git pull`, it will cause the parent repo to think that there are changes that need to be committed. To solve this problem, I have the script descend into submodules first, create any necessary commits (along with the usual pull and push steps), then proceed up the tree.

Here's what a typical run of the script looks like:

```

[~/obsidian-vault/_modules/elliotwinkler.com/modules/personal-content--writings] Pushing `main`...
[~/obsidian-vault/_modules/elliotwinkler.com/modules/personal-content--writings] Sync completed successfully!
```

### Updating the deployment process

The deployment process for my site also works differently now.

I have always made it possible to deploy a preview build while writing a draft. This allows me to see what a post looks like on the site before it goes live. But previously, the way that I would manage these two environments worked like this:

- If I wanted to deploy my site to production, I could push a commit to `main`, either on the site repo or content repo.
- If I wanted to deploy a preview build, I would have to make a pull request on either my site repo or my content repo.

(Hence the complicated list of steps at the start of this whole section.)

Switching to submodules, though, meant that there were going to be a lot of pushes straight to `main` for both site and content repos. I didn't want to deploy the production site every time that happened, so now the way it works is:

- Pushing to `main` on either the site repo or the content repo deploys a preview build. That means if I update a draft blog post in Obsidian, I can see what it will really look like within about 30 seconds.
- If I want to deploy to production, I have to go on my laptop and trigger it manually from the Vercel dashboard.

I don't publish blog posts that often, so I think that's an acceptable tradeoff.

### Reconfiguring Obsidian

By default, Obsidian only lets you see and work with `.md` files; if there are any other files present in your vault, it ignores them.

Since blog posts on my site are written in MDX files, however, I need to make them visible. There doesn't seem to be an official way to do this, but I've found the Custom File Extensions plugin, and although it is a bit overengineered for my liking, it seems to fit the bill.

### Updating the site repo

Obsidian implements a superset of CommonMark, aptly called [Obsidian Flavored Markdown](https://help.obsidian.md/obsidian-flavored-markdown). In order for posts to appear the same way they do on Obsidian, I've updated my site to support the following two features:

- [Comments](https://help.obsidian.md/syntax#Comments). These are designated using `%%...%%` instead of `<!--...-->`.
- [Callouts](https://help.obsidian.md/callouts). These are very similar to [GitHub's alerts feature](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#alerts), except that callout types are allowed to be lowercase, and there are a lot more types supported. [^4] Thankfully, someone created [`rehype-callouts`](https://github.com/lin-stephanie/rehype-callouts), and this works very well.

### Initializing the vault repo

The sync script assumes that `main` is checked out for all repos, as each time it runs, it needs to pull the latest changes to that branch. This  means that when I have to download (or re-download) my vault repo, a simple `git clone` won't do, nor will `git submodule update --init`; I have to go into each submodule and manually check out `main`. It's a bit of a pain, and I'm sure I'll make it better, but fortunately it's not something I have to do often.
